Boris：我觉得很多人一想到 AI，想到的就是聊天机器人。而对工程师来说，也许大概一年半以前，在我们开始做 Claude Code 之前，AI 对大多数人来说就是聊天机器人。我们在某个时刻意识到，模型在写代码这件事上其实变得非常厉害了，而且在使用工具方面也变得越来越强。而这些其实是我们一直以来训练模型去做的事情。这作为研究方向其实已经有一段时间了。它大概在一年半以前开始变得有商业价值。所以在 Claude Code 上，我们下了一个赌注，并且偏离了当时所有人写代码的方式，因为当时全世界写代码的方式本质上就是用一种高级的文本编辑器。而我们只是想，也许我们能做得比这好得多，做出一些和以往截然不同的东西。这完全就是一场赌注。于是我们推出了 Claude Code。而让 Claude Code 和当时的聊天机器人不同的地方在于，Claude Code 可以使用工具。这就是关键，这就是区别所在。用聊天机器人，你是来来回回地在对话；但一个智能体，而 Claude Code 就是一个智能体，它能使用你的工具。

Kantrowitz：对吧？那我们能不能快速定义一下工具？工具可以是任何东西，你告诉我对不对：从使用浏览器，到登录 Cloudflare，然后通过那种方式搭建某个智能体，对吧？所以问题越来越不是「这个产品本身能做什么」，而更像是「这个产品能登录进什么，然后用你能在网上使用的这一大堆产品去做什么」。

Kantrowitz：是啊。我觉得这里最根本的一点，值得再往下深挖一下，就是 AI 似乎已经从「擅长自动补全」这种定位转变了，对吧？因为在最底层，AI 其实就是在预测接下来会出现什么。比如你用机器学习把它应用到一个大数据集上，预测你是否可能拖欠房贷、银行该不该批这笔房贷。放到一句话里，就是预测下一个词；放到代码里，就是预测序列中的下一段代码，对吧？所以我觉得那是第一代。而你现在说的是，机器实际上已经能够在拿到你给的自然语言提示之后，自己去写代码、接入工具，然后替你做事。所以如果我没理解错的话，这里的用例已经从「开发者接入它、用 Claude Code 写代码」——我们已经看到了由他们推动的这场爆发——扩展到了第二股力量，也就是非技术人群，像我这样的人，可以通过指挥 AI 智能体，也就是 Claude Code，来为他们构建一个工作流软件、一个网站，或者通过像 Claude Co-Work 这样的东西来接管你的电脑。Co-Work 我大概会把它叫作更亲民的姐妹产品。然后你可以说：「好，你能访问我的浏览器，你知道我喜欢订什么样的航班，我几周后得去一趟印度，帮我把机票订了。」

Kantrowitz：但现在我想对这个论点稍微做一下压力测试，提一些让我好奇的事：这里面有多少是真实的，又有多少只是对潜力的、不受约束的热情，而有些也许我们该现实地审视一下。第一件事是，需求确实非常旺盛，但问题是，其中有多少是纯粹的需求，又有多少是被「游戏化」出来的需求。硅谷内外都有一种做法正在流行，叫 tokenmaxxing。你肯定听说过。就是有些公司下达指令，要求员工尽量多地使用 AI token，让他们的 AI 智能体尽可能多地跑起来。然后那些用掉最多 token 的人，会在排行榜上被奖励，或者达到一个他们必须完成的「AI 行动」目标。

Kantrowitz：我在 Facebook 待过。

Kantrowitz：没错，没错。

Boris：是啊。

Boris：我当时的一项职责，是负责 Meta 旗下所有应用代码的健康状况。也就是 Facebook、Instagram、WhatsApp 这些。我们之所以关心代码的健康，本质上就是代码质量这类东西，是因为如果代码质量真的很高，工程师的生产力就会更高。当时有一大票人在做生产力相关的工作。在模型出现之前、在 Claude 出现之前，你可能要努力工作很久，一年下来每个工程师的生产力也许能提升 1%、2%、3%，大概就是那个量级。而那已经算是相当大的提升了，而且非常来之不易。你基本上得尝试一大堆想法，最后才找到某个能像这样提升生产力的东西。而 Claude 出现之后，现在包括 Anthropic 和我们所有最大的客户在内的许多公司，报告的提升都是数百个百分点这个量级的。我想我们上次公布的数字是，自从引入 Claude Code 以来，Anthropic 每个工程师编写的代码量增长了大约 250%，而且这是在保持代码质量、可靠性等等基本稳定的前提下实现的。也就是说在这些指标没有倒退的情况下，代码量大幅增长。所以这种对生产力的影响，我觉得是非常新的，而人们正在努力搞清楚怎么才能获得它。有很多公司在问：我们怎么才能拿到这样的收益？因为很多公司已经看到了，还有一些仍在摸索中。而我的建议几乎总是一样的。第一件事，就是给每个人 token，让人们去实验。我不一定推荐 tokenmaxxing，但我确实推荐让人们去实验，这样他们就不用为每一点 token 都去申请批准。第二件事，是给人心理上的安全感，因为很多时候人们在创新、在打造让自己更高效的工具时，他们是在改变自己的 workflow 来让自己更高效。他们会尝试一堆想法，有些可能行不通，然后有些行得通。所以你要给人们这种心理上的安全感，让他们觉得可以放心地去实验、去发现这些新的流程。

Kantrowitz：是啊，而且我得说，我自己也用很多 token，我一直泡在这些工具里。我觉得 Claude Code 和 Claude Co-Work 对我的业务都相当不错。我是一个人单干，虽然这么说也有点把它说小了，因为我背后其实有一支团队在帮我，大多是兼职形式，不过那是另一期节目的话题了。但我的确有点好奇：当我读到这些报道时，大公司在这些预算里占了很大很大的比例，而激励这东西——你知道，我在节目开场就说过，这一切到底有多可持续——在某些地方激励是扭曲的。这是最近《Financial Times》的一篇报道：亚马逊员工用 AI 工具做不必要的任务，来虚增使用分数。一些员工说，同事们在用这个软件去自动化额外的、不必要的 AI 活动，以增加自己的 token 消耗。他们说，此举反映出在亚马逊引入「每周 80% 以上开发者必须使用 AI」的目标之后，大家被迫采用这项技术的压力。我向一位亚马逊员工求证了这件事，他说：「对，情况就是这样。」他们告诉我：「我触发了一个自动化任务，让它跑上好几个小时，然后每天再把它删掉，就为了达成这些指标。」所以你说你并不认为这种 tokenmaxxing 是需求中很大的一部分。那么从你这边，有没有任何东西能表明这只是个例，而不是大多数地方的常态？

Kantrowitz：对吧？而且它大概也会延伸到你使用聊天机器人的方式上。有意思的是，Anthropic 和聊天机器人之间一直有种挺微妙的关系：一开始是技术优先，后来决定做聊天机器人、发布 Claude，然后又有点转向企业市场。你看那些图表，Claude 总是排在最底下。但现在你看到 Claude 的使用量在上升。我有个想法，想跟你核对一下：聊天机器人的未来，不是「我问你一个问题，你给我一个答案」，而是「我问你一个问题，或者跟你聊一个难题，然后你——聊天机器人——会主动建议你能替我采取某种行动」。就像现在我一直在聊去印度旅行的事，而我觉得未来我得到的回复会是这样的：就像你说的那样，不再需要「还得自己去那儿订机票」这个中间步骤，而是一个更主动的聊天机器人，它会说：「好，这件事交给我来帮你办。」这个方向对吗？我这么想对不对？

Boris：我能看到那种可能，能，能。

Kantrowitz：你们在做这个吗？

Boris：智能体就是未来，而我们在尝试各种各样不同的实验。有一些我们正在尝试的东西，确实是这个方向的。是的。

Kantrowitz：好。但这里总归有个极限，对吧，它总有做不到的地方。人们谈到「你能并行运行成千上万个 Claude」这件事的极限时，有种挺有意思的角度，就是去看 Anthropic 在招什么样的人。Anthropic 网站上我最喜欢的招聘启事，就是你们在招 Salesforce 管理员。你们还在招顾问，帮企业部署这项技术。而很多人把这看作一种心照不宣的承认：这东西能带你走的距离也就这么远。沃顿商学院教授 Ethan Mollick 是这么说的：「当这些 AI 实验室解散他们新组建的咨询团队——抱歉，是前置部署工程（forward deployed engineering）团队时，你就知道他们是真的相信人工超级智能了。只要还需要人去搞清楚 AI 到底有什么用、去做组织变革和系统集成，工作看起来就还挺安全的。」你怎么看？

Boris：是啊。嗯，你看看我做的那种工程工作：我不写代码，我用提示词驱动 Claude。其实现在大多数时候，我是让一个 Claude 去提示其他 Claude。所以我甚至不直接和 Claude 说话，而是让一个 Claude 在替我和我的 Claude 们对话。而我觉得在工程领域，你已经看到单个人所能拥有的杠杆出现了爆炸式增长。这关乎的是：一个人能撑起多大的生意？一个人能支撑多少产品？现在在 Anthropic，一个工程师所拥有的杠杆简直疯狂。而我觉得我们也开始在其他学科里看到这一点了。我们开始在市场人员身上看到，他们用 Claude 做各种事情；我们也开始在前置部署工程师身上看到，他们用 Claude Code 来构建实现；我们还在销售团队身上看到这一点，因为其实在 Anthropic，我觉得大概有一半的 go-to-market 团队在用 Claude Code，另一半在用 Co-Work。我觉得每个人都在用所有这些产品。所以我们看到的是，个人所拥有的杠杆在上升，而我们仍然受制于「足够优秀的人数」这个瓶颈。所以即便每个人的杠杆都在上升，你还是招不到足够多的优秀人才，因为需求实在太疯狂了，而且还有太多东西要去构建。所以这仍然是我们的瓶颈。Kantrowitz：但我会说，有人会反驳说，如果这东西真有那么强，那它应该能看一眼我的销售组织是怎么运作的，然后用一句提示词就把 Salesforce 配置成那个样子。这算不算——人们还举了另一个例子：如果 Anthropic 的 AI 真有那么强，那我就相信它了，前提是它能让 AI 去处理 IPO 的文件，而不是去请一家投行。这些是不是不公平的测试？

Boris：嗯，我们已经开始看到，团队里有一个人在用 Claude 报税。

Kantrowitz：嗯，你知道，我不一定推荐这么做，但我承认我把自己的报税也丢给 Claude 跑了一遍，然后拿去和我的会计师对了一下，结果还挺接近的。

Boris：是啊，我也干过同样的事。

Kantrowitz：各位，这不是在建议你们也这么做，但这确实是。

Boris：一个挺有意思的用例。

Boris：没错。但我觉得，在这场讨论里，人们根本上忽略了一点：到最后，还是得由一个人去和 Claude 说话，让 Claude 去做这件事。所以即便 Salesforce 是自动配置的，不是一个人在那儿按所有按钮，而是 Claude 在做，也总得有人去让 Claude 做这件事。而如果你得用一大堆不同的方式去配置 Salesforce，那「让 Claude 去做这件事」本身，其实就可能是一份全职工作。而在某个节点，Claude 会变得非常擅长「让 Claude 去做这件事」，于是那个人就会去「让那个去让 Claude 做事的 Claude 去做这件事」。这条链条只会不断越变越深。但到头来，你仍然需要有人在驾驭这一切。

Kantrowitz：但也许在未来，他们的工作就只是问一个问题而已。

Boris：是啊。但你想想，问对那个问题，能带来多大的杠杆。

Kantrowitz：这倒也是，说得有道理。嗯，既然聊到了 Salesforce，那我们就得聊聊 SaaS 末日（SaaS apocalypse）。你对哪些类型的软件公司在自动化编程越来越强的情况下会是安全的、哪些可能会有麻烦，有一些挺有意思的看法。你之前也谈过不同的护城河（moat），哪些护城河更重要、哪些没那么重要。在我们聊到这个的时候，你能简要分享一下吗？Boris：有一个很棒的框架，叫 Seven Powers（七种力量），专门用来讨论商业里的护城河。这种框架有很多，但这是我最喜欢的一个。我在学校里其实学的是经济学，不是计算机科学，所以这仍然是我思考问题的方式，就是用这种框架。商业里有各种各样不同的护城河，有的公司有一条，有的公司有几条，相当于一个护城河的组合。护城河有很多条，比如其中一条是规模经济：随着你扩大生产规模，就会出现规模报酬递增。另一条是网络效应：比如一个即时通讯应用之类的东西，用的人越多，对任何一个人来说它就越有价值。还有一条是转换成本，还有一条叫流程能力（process power）。我觉得这些护城河大多数在未来仍然重要，只不过相对而言，有些在明年会变得更重要，有些会变得没那么重要。我认为会变得更重要的，是网络效应这一类东西，因为谁在写代码并不重要，你的产品核心是一个智能体还是别的东西也不重要，你的产品里有没有智能也不重要；如果你的产品里有网络效应，那它仍然会重要。有些护城河会变得更不重要，比如转换成本，因为如果你想从供应商 A 换到供应商 B，你只要让 Claude 去做就行了，而 Claude 在这件事上会随着时间的推移变得越来越擅长。所以作为一家公司，你应该思考的一件事是：你的护城河是什么？而我觉得很多最大的公司都有很多很多护城河，而不是只有一条，因为你实现规模化、长期建立起一家有防御能力的公司的方式，就是不断积累这些护城河，你需要有好几条。但归根结底，我只会去想：在这里面，什么会变得更有价值，什么会变得没那么有价值。

Kantrowitz：不过我觉得，当你去想这些不同的软件公司时，如果你在用 Claude Code，那是不是所有护城河最终都会变得模糊？因为你可能最终会处在一个应用里，由它来对接所有软件，那是不是就意味着其实只剩下一家软件公司了？

Kantrowitz：好。我特别想听听你对「世界模型（world model）」这场争论的看法。支持世界模型的人说，大语言模型并不理解后果，你必须把一个世界模型内置进去，才能拥有真正有效的智能体。Yann LeCun 是这么说的：「没有世界模型，你就不可能构建一个可靠的智能体式系统。大语言模型没有世界模型，它们无法在采取行动之前预测自己行动的后果。」按照 Yann 的说法，它们只是行动，而接下来发生什么都是别人的问题。我最近和 OpenAI 的 Greg Brockman 聊过，他说他基本上不接受这个论点，他认为大语言模型才是那条路，这些文本模型就是通往 AGI 的路。你站哪一边？你是否相信世界模型这种智能需要被内置进去，还是你认为大语言模型本身就足够了？Boris：我想给 Yann 发个邀约：如果他愿意坐下来和我一起用 Claude Code 写一个小时代码，我很乐意展示给他看。然后——
