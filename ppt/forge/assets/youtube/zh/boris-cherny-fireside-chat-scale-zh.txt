主持人：对，这真的很酷。Workflow 是个相当新的概念，我好像看到过相关的公告，不知道在座有多少人熟悉，但这似乎又是一个值得我们盯紧的东西。那能不能用一句话概括下 workflow 和 loop 的区别，还是说它们差不多是一回事？

Boris：嗯，还挺不一样的。我会这么理解：AI 里有那些传统的 scaling law（缩放定律），早些时候有一篇 scaling law 的论文提出了这个想法：transformer 怎么 scale、LLM 怎么 scale，它是数据量、神经网络规模，以及用来训练这个神经网络的算力这三者的函数。这就是模型那种指数级的特性，也是为什么智能一直在指数级增长——就是因为这三个缩放因子。而过去几年发生的事是，我们又加了第四个因子，叫 test time compute。说白了，test time compute 其实就是个花哨的说法，意思就是：模型生成了多少个 token。就这么简单。所以有一些办法能让模型"有产出地"生成更多 token，从而拿到更好的结果。有几种做法。第一种是 effort 设置。对 Claude 模型来说，有 low effort、medium、high、extra high、max，这是一种配置你 basically 想让模型输出多少 token 的方式，这是在调 test time compute 的行为：token 越多，结果越好。第二种做法是我们刚推出的 dynamic workflow。它用 Claude 去写一个类似小程序的东西，这个程序实际上跑在一台虚拟机里，去编排其他的 Claude 来解决一个问题。这是一种我们还在探索的新形式 test time compute，但本质上，它就是一种让 Claude 去拉起几十个、几百个、上千个智能体来把活干完的方式。

Boris：比如：我能跑这条 bash 命令吗？我能用这个 MCP 吗？我能在浏览器里 fetch 这个 URL 吗？行还是不行。坐在那儿的工程师就得批准或拒绝，说行或不行。而我们发现的一件事是：时间一长，人就会变得有点懒，至少对我来说，我就一直点"是"，根本没真的在读那些命令。我相信这对很多人也都成立——不知道你们会不会跟老板承认这个，但……

Boris：它的作用是：任何时候 Claude 要做一处改动，它都会给你解释：嘿，这个架构是这么工作的；这个语言如果你以前没用过，它是这么工作的；代码库的这一部分是这么工作的。它会解释给你听，这样你就能学。然后还有一个 learning output style（学习型输出风格），是给不会写代码的人用的。它会跟他们解释：嘿，这门语言是这么工作的；在非常基础的层面，它会教你怎么去做这件事，而不是替你把事做了。所以它会这样：好，在 JavaScript 里，比如说，某个东西是这么工作的，我不替你改，我带你过一遍。第一步，打开这个文件，按这种方式编辑。第二步，跑这条命令。

Boris：好，我看到你做了。第三步，做这个。所以我真的觉得 output style，以及更多地去用 Claude，是一种极其强大的学习工具。它也能帮我作为工程师去理解正在发生什么——哪怕我们的技术栈在变、基础设施在变，尤其是当我在用一门新语言的时候。
