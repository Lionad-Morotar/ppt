# AI Native 工程团队，应当凑齐哪五种人

> Claude Code 缔造者 Boris Cherny 眼中的五种新角色

五月份的时候，关于产研团队的 AI 入门，我分享了核心观点：

1. 专业产出仍需要人工垫中间产物
2. 使用 Claude Code、Cowork 等集成工具而不是助手，能减少任务过程中上下文切换带来的损耗
3. LLM 的输出概率性的
4. 梯度优化：LLM 的学习是通过调整权重不断减小损失，直到输出足够接近正确答案
5. Token：LLM 输入和输出的最小单位
6. 和模型对话在工程上是把角色拆成用户/助手，让模型做"对话补全"
7. Agent：用 ReAct 循环让概率性输出尽可能确定
8. ReAct 循环：推理→调用工具→观察结果→判断，循环直到LLM决定组织最终回答
9. MCP：LLM 链接外部工具和资源的协议
10. RAG：先检索知识库再生成，解决 LLM 知识范围限制
11. OpenClaw 和 Claude Code 在 ReAct Loop 上一致的
12. Harness = 产品 - Agent，产品差距不在模型，而在 Harness

结论的层次仍然停留在智能体本身

两个月来，对 AI 原生工程团队积累了少许认识，今天简单给大家梳理一下（梳理什么呢？）

一些观点仍然基于之前的分享，但加以深化：

1. LLM 的概率性机制，决定了在生产系统的 Harness 应当"先守底线、再提上限"
2. 把 AI 原生工程把 AI 内嵌端到端，但仍只是"单点提效"；要十倍提升，必须重构协作模式。
4. AI 原生工程团队的本质：研发流程持续压缩、Harness 持续左移，催生"超级个体"
